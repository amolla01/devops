How ProxyJump Works
Your laptop cannot directly reach 172.16.2.x (it's a private OVS bridge inside the hypervisor). SSH ProxyJump opens a connection to the hypervisor first, then tunnels a second SSH session from there to the VM. This is transparent — you just type ssh 172.16.2.11 and it works.

3Windows Hosts File (/etc/hosts equivalent)

Do you need a hosts file?
Yes — while not strictly required (you can use IPs directly), adding hostnames to your Windows hosts file lets you use friendly names like ssh spine-s1 and makes Ansible inventory more readable. It also enables kubectl to resolve the K8s API server by name.

Edit the Windows hosts file

Open PowerShell as Administrator:

# Open hosts file in Notepad (elevated)

Important — WSL2 shares the Windows hosts file
WSL2 automatically reads C:\Windows\System32\drivers\etc\hosts via /etc/wsl.conf (unless you've disabled generateHosts). So these entries work in both PowerShell and WSL2 shells.
iDRAC / PXE entries are optional for KVM lab
The 192.168.255.x entries only matter when targeting real hardware (profile: real_hardware). In the KVM lab, all VMs are reached via 172.16.2.x through the hypervisor's OVS bridge. Include them if you plan to access iDRAC web interfaces from your laptop via a separate route/VPN.

# WSL2
getent hosts spine-s1    # Should show 172.16.2.11

4SSH Key Generation

WINDOWS Generate an ED25519 key pair

# PowerShell (no elevation needed)
ssh-keygen -t ed25519 -f "$env:USERPROFILE\.ssh\id_dc_lab" -C "dc-lab-ansible" -N ""

This creates:

  • C:\Users\nh4134\.ssh\id_dc_lab — Private key
  • C:\Users\nh4134\.ssh\id_dc_lab.pub — Public key

HYPERVISOR Copy public key to hypervisor

# PowerShell — copy pub key to hypervisor's authorized_keys
type $env:USERPROFILE\.ssh\id_dc_lab.pub | ssh user@192.168.9.200 "mkdir -p ~/.ssh; cat >> ~/.ssh/authorized_keys; chmod 600 ~/.ssh/authorized_keys"

Verify passwordless login

# Should connect without password prompt
ssh -i $env:USERPROFILE\.ssh\id_dc_lab user@192.168.9.200 "hostname; uptime"

5SSH Config (ProxyJump)

Create/edit C:\Users\nh4134\.ssh\config

# ═══════════════════════════════════════════════════════════════════
# DC CLOS KVM Lab — SSH Configuration
# ═══════════════════════════════════════════════════════════════════
# This file enables transparent SSH to lab VMs from Windows laptop.
# VMs are on 172.16.2.0/24 (OVS br-mgmt) — only reachable via hypervisor.
# ═══════════════════════════════════════════════════════════════════

# --- Hypervisor (direct access from laptop) ---
Host dc-hypervisor dc-hyp ubuntu-r620 192.168.9.200
    HostName 192.168.9.200
    User user
    IdentityFile ~/.ssh/id_dc_lab
    ForwardAgent yes
    ServerAliveInterval 60
    ServerAliveCountMax 3

# --- SONiC Switches (all on 172.16.2.x, jump via hypervisor) ---
Host spine-s1 Spine_S1
    HostName 172.16.2.11

Host spine-s2 Spine_S2
    HostName 172.16.2.12

Host leaf-l1 Leaf_L1
    HostName 172.16.2.21

Host leaf-l2 Leaf_L2
    HostName 172.16.2.22

Host leaf-l3 Leaf_L3
    HostName 172.16.2.23

Host leaf-l4 Leaf_L4
    HostName 172.16.2.24

Host border-leaf1 Border_Leaf1
    HostName 172.16.2.31

Host border-leaf2 Border_Leaf2
    HostName 172.16.2.32

# --- Exit Routers (MikroTik CHR) ---
Host exit-router1 Exit_Router1
    HostName 172.16.2.98
    User admin

Host exit-router2 Exit_Router2
    HostName 172.16.2.99
    User admin

# --- Servers (Ubuntu — Compute + K8s) ---
Host host12-1 Host12_1
    HostName 172.16.2.40

Host host12-2 Host12_2
    HostName 172.16.2.41

Host host12-3 Host12_3
    HostName 172.16.2.42

Host host34-1 Host34_1
    HostName 172.16.2.43

Host host34-2 Host34_2
    HostName 172.16.2.44

Host hostb12-1 HostB12_1 k8s-master
    HostName 172.16.2.45

Host hostb12-2 HostB12_2
    HostName 172.16.2.46

# --- Monitoring Server ---
Host monitor-srv MonitorSrv
    HostName 172.16.2.47

# --- Dedicated Ceph Storage Servers ---
Host storage-hdd-01 Storage_Server_HDD_01
    HostName 172.16.2.50

Host storage-hdd-02 Storage_Server_HDD_02
    HostName 172.16.2.51

Host storage-ssd-01 Storage_Server_SSD_01
    HostName 172.16.2.52

Host storage-ssd-02 Storage_Server_SSD_02
    HostName 172.16.2.53

# --- iDRAC / PXE subnet (real hardware — optional for KVM lab) ---
Host 192.168.255.*
    ProxyJump dc-hypervisor
    User root
    StrictHostKeyChecking no
    UserKnownHostsFile /dev/null
    ConnectTimeout 10

# --- Wildcard: ALL 172.16.2.x hosts jump through hypervisor ---
Host 172.16.2.*
    ProxyJump dc-hypervisor
    User admin
    IdentityFile ~/.ssh/id_dc_lab
    StrictHostKeyChecking no
    UserKnownHostsFile /dev/null
    ConnectTimeout 10

# --- Named hosts inherit the wildcard (explicit ProxyJump) ---
Host spine-* Spine_* leaf-* Leaf_* border-* Border_* exit-* Exit_* host* Host* monitor-* Monitor* storage-* Storage_*
    ProxyJump dc-hypervisor
    IdentityFile ~/.ssh/id_dc_lab
    StrictHostKeyChecking no
    UserKnownHostsFile /dev/null
    ConnectTimeout 10
How it works
  • The Host 172.16.2.* wildcard catches any direct IP reference
  • Named hosts (spine-s1, host12-1, etc.) match the named Host blocks
  • Both route through ProxyJump dc-hypervisor
  • ForwardAgent yes on the hypervisor forwards your key to VMs (for git/scp from VMs)

6Distribute SSH Keys to VMs

HYPERVISOR One-time: push public key to all VMs

SSH into the hypervisor and distribute your public key to each VM:

# SSH into hypervisor first
ssh dc-hypervisor

# Copy the public key to the hypervisor (if not already there)
# From your laptop: scp ~/.ssh/id_dc_lab.pub dc-hypervisor:~/

# Distribute to SONiC switches (default password: YourSonicPa55)
for ip in 172.16.2.{11,12,21,22,23,24,31,32}; do
  sshpass -p 'YourSonicPa55' ssh-copy-id -i ~/id_dc_lab.pub \
    -o StrictHostKeyChecking=no admin@$ip 2>/dev/null && echo "✓ $ip" || echo "✗ $ip"
done

# Distribute to Ubuntu servers (default password: ubuntu)
for ip in 172.16.2.{40,41,42,43,44,45,46,47}; do
  sshpass -p 'ubuntu' ssh-copy-id -i ~/id_dc_lab.pub \
    -o StrictHostKeyChecking=no ubuntu@$ip 2>/dev/null && echo "✓ $ip" || echo "✗ $ip"
done

# Distribute to dedicated Ceph storage servers (default password: ubuntu)
for ip in 172.16.2.{50,51,52,53}; do
  sshpass -p 'ubuntu' ssh-copy-id -i ~/id_dc_lab.pub \
    -o StrictHostKeyChecking=no ubuntu@$ip 2>/dev/null && echo "✓ $ip" || echo "✗ $ip"
done

# MikroTik CHR — uses different SSH key import method
for ip in 172.16.2.{98,99}; do
  scp -o StrictHostKeyChecking=no ~/id_dc_lab.pub admin@$ip:/id_dc_lab.pub
  ssh -o StrictHostKeyChecking=no admin@$ip "/user ssh-keys import public-key-file=id_dc_lab.pub user=admin"
done

7Verify SSH Connectivity

WINDOWS Test from PowerShell

# Test hypervisor (direct)
ssh dc-hypervisor "hostname && uptime"

# Test SONiC switch via ProxyJump (should work transparently)
ssh spine-s1 "show version"
ssh 172.16.2.21 "show interfaces status"

# Test Ubuntu server via ProxyJump
ssh host12-1 "hostname && ip addr show | grep inet"
ssh hostb12-1 "kubectl get nodes 2>/dev/null || echo 'K8s not yet deployed'"

# Batch connectivity check (all VMs)
for vm in spine-s1 spine-s2 leaf-l1 leaf-l2 leaf-l3 leaf-l4 border-leaf1 border-leaf2 host12-1 host12-2 host12-3 host34-1 host34-2 hostb12-1 hostb12-2 monitor-srv storage-hdd-01 storage-hdd-02 storage-ssd-01 storage-ssd-02; do
  ssh -o ConnectTimeout=5 $vm "hostname" 2>/dev/null && echo "✓ $vm" || echo "✗ $vm"
done

ln -sf /mnt/c/Users/nh4134/.ssh/id_dc_lab ~/.ssh/id_dc_lab
chmod 600 ~/.ssh/id_dc_lab ~/.ssh/config
Permission fix for SSH keys in WSL
Windows filesystem (/mnt/c/) shows all files as 777. If SSH complains about key permissions, either copy the key into WSL's native filesystem or add to /etc/wsl.conf: 
[automount]
options = "metadata,umask=022,fmask=077"
Then restart WSL: wsl --shutdown

Alternative: Native Windows Ansible (via pip)

# PowerShell (if you prefer not to use WSL)
pip install ansible
# Note: Some modules may not work natively on Windows.
# WSL2 is strongly recommended for Ansible.

9Ansible Configuration (ansible.cfg)

Create ansible.cfg in your project root (next to playbooks):

[defaults]
inventory = inventory/hosts.yml
remote_user = admin
host_key_checking = False
timeout = 30
forks = 10
gathering = smart
fact_caching = jsonfile
fact_caching_connection = /tmp/ansible_facts
fact_caching_timeout = 3600
stdout_callback = yaml
callbacks_enabled = profile_tasks

[ssh_connection]
# ProxyJump is configured in ~/.ssh/config — Ansible uses it automatically
ssh_args = -C -o ControlMaster=auto -o ControlPersist=600s -o StrictHostKeyChecking=no
pipelining = True
retries = 3

[privilege_escalation]
become = False
become_method = sudo
become_ask_pass = False
ProxyJump is automatic
Because ~/.ssh/config already defines ProxyJump for 172.16.2.*, Ansible does not need any special ansible_ssh_common_args. It simply calls ssh 172.16.2.11 and your SSH config handles the jump.

deploy_lab_v13.sh MUST run ON the hypervisor

13Remote kubectl Access

After Kubernetes is deployed on HostB12_1 (172.16.2.45), you can access it from your laptop:

Option A: SSH tunnel (recommended)

# Open a persistent tunnel to the K8s API server
# (K8s API runs on HostB12_1:6443)
ssh -f -N -L 6443:172.16.2.45:6443 dc-hypervisor

# Then use kubectl locally
export KUBECONFIG=~/.kube/dc-lab-config
kubectl get nodes
kubectl get pods -A

Create the kubeconfig

# Fetch kubeconfig from HostB12_1
ssh hostb12-1 "sudo cat /etc/kubernetes/admin.conf" > ~/.kube/dc-lab-config

# Replace the server address to use the tunnel
# From: server: https://172.16.2.45:6443
# To:   server: https://127.0.0.1:6443
sed -i 's|server: https://172.16.2.45:6443|server: https://127.0.0.1:6443|' ~/.kube/dc-lab-config

# Set context
export KUBECONFIG=~/.kube/dc-lab-config
kubectl cluster-info

Option B: SOCKS proxy (alternative)

# Create SOCKS5 proxy through hypervisor
ssh -f -N -D 1080 dc-hypervisor

# Use with kubectl via HTTPS_PROXY
HTTPS_PROXY=socks5://127.0.0.1:1080 kubectl get nodes

14Troubleshooting

SymptomCauseFix
ssh: connect to host 172.16.2.x: Connection timed out ProxyJump not configured or hypervisor unreachable Verify ssh dc-hypervisor works first. Check ~/.ssh/config has the ProxyJump wildcard.
Permission denied (publickey) Key not distributed to VM Re-run key distribution (Step 6). Or use -o PasswordAuthentication=yes with sshpass.
WARNING: UNPROTECTED PRIVATE KEY FILE! Key file has wrong permissions (WSL /mnt/c issue) Copy key to WSL native: cp /mnt/c/Users/nh4134/.ssh/id_dc_lab ~/.ssh/; chmod 600 ~/.ssh/id_dc_lab
kex_exchange_identification: Connection closed VM not booted or SSH service not running SSH to hypervisor → virsh list --all → start the VM → wait 60s for SSH to come up.
Ansible: unreachable for all hosts SSH config not visible from WSL Symlink: ln -sf /mnt/c/Users/nh4134/.ssh/config ~/.ssh/config
Ansible: Failed to connect to the host via ssh SSH ControlMaster stale socket rm -rf ~/.ansible/cp/* then retry
host key verification failed VM was redeployed (new host key) Already handled by StrictHostKeyChecking=no in config. If not: ssh-keygen -R 172.16.2.x
Ansible: No such file or directory: '/mnt/c/...' Path too long / Windows path in WSL context Clone repo inside WSL native filesystem: git clone ... ~/dc-lab
ProxyJump: command not found OpenSSH client too old (<7.3) Update OpenSSH: winget install Microsoft.OpenSSH.Beta or use ProxyCommand ssh -W %h:%p dc-hypervisor instead
