1. Overview & Traffic Flow

1.1 Egress (Host downloads from the internet)

Host12_1 (10.10.255.1) │ default route via FRR BGP ▼ Leaf_L1 / Leaf_L2 ── eBGP ── Spine_S1 / Spine_S2 │ eBGP ▼ Border_Leaf1 / Border_Leaf2 │ eBGP /31 link ▼ Exit_Router1 / Exit_Router2 │ MASQUERADE (SNAT) ▼ ether1 ── Internet / WAN

How it works: The exit routers advertise a 0.0.0.0/0 default route into the BGP fabric via output.default-originate=always. Every switch and server in the CLOS fabric receives this route through the eBGP chain. When a host sends a packet to the internet, it follows the default route through the spine → border-leaf → exit-router, where source NAT (masquerade) translates the internal IP to the exit router's external address on ether1.

1.2 Ingress (External user accesses a service inside)

Internet / User │ ▼ Exit_Router (ether1) ── DST-NAT (port forward) ── translate to internal IP │ ▼ Border_Leaf ── eBGP ── Spine ── eBGP ── Leaf │ ▼ Host (VM running service)

How it works: A DNAT (destination NAT) rule on the exit router maps an external port to an internal host:port. Return traffic is automatically handled by connection tracking.

4. Deployment Procedure (Step-by-Step)

4.1 Prerequisites

  • Border leaves already configured and BGP established with spines (via deploy_day0.yml + deploy_day1.yml).
  • MikroTik CRS326 exit routers powered on and reachable via SSH at 172.16.2.98/99.
  • External interface (ether1) physically connected to ISP/campus uplink.

4.2 Execution Order

1 Wire Border Leaves to Exit Routers (day-1 fabric link)
ansible-playbook playbooks/deploy_day1_v2.yml -i inventory/hosts.yml --limit border_leaves,exit_routers
Configures the /31 eBGP point-to-point link between Border_Leaf Ethernet0 and Exit_Router sfp+1.
2 Deploy full exit router configuration (identity, BGP, NAT, firewall)
ansible-playbook playbooks/deploy_exit_routers.yml -i inventory/hosts.yml
Runs all 6 phases: preflight → base → BGP → NAT → firewall → verify.
3 Verify internet reachability from any host
ssh admin@Host12_1 "ping -c 3 8.8.8.8"
If successful, the default route and masquerade are working end-to-end.
4 (Optional) Add inbound port forwards
Add DNAT rules for services you want externally accessible. See Section 8.
Idempotent

Both playbooks are safe to re-run. MikroTik commands use failed_when: false to tolerate "already exists" responses, and SONiC config is rendered then applied.

5.2 What happens in the fabric

Once BGP establishes between Exit_Router and Border_Leaf, the default route propagates:

Exit_Router1 → Border_Leaf1 → Spine_S1/S2 → Leaf_L1/L2/L3/L4 → Host FRR
Exit_Router2 → Border_Leaf2 → Spine_S1/S2 → Leaf_L1/L2/L3/L4 → Host FRR

Every server receives two equal-cost default routes (ECMP) — one via each exit router path. If one exit router goes down, BGP withdraws its route and traffic fails over automatically.

6. NAT — Source NAT (Masquerade)

6.1 What is configured

# On each exit router:
/ip firewall nat add chain=srcnat out-interface=ether1 \
  src-address=10.0.0.0/8 action=masquerade comment=fabric-snat-10.0.0.0_8

/ip firewall nat add chain=srcnat out-interface=ether1 \
  src-address=172.16.2.0/24 action=masquerade comment=fabric-snat-172.16.2.0_24

6.2 Source ranges covered

RangeWhat it covers
10.0.0.0/8Loopbacks (10.0.x.x), server VTEP IPs (10.10.255.x), P2P links (10.0.253.x)
172.16.2.0/24Management network (all switch and host management IPs)

6.3 External interface

ether1 is the internet-facing port. This should be connected to your ISP or campus uplink. The masquerade rule rewrites the source address of outgoing packets to the IP assigned on ether1.

8. Inbound Access (Port Forwarding / DNAT)

To expose an internal service to the outside world, add a destination NAT rule. This is not automated by default — add manually or extend the playbook.

8.1 Example: Expose a web service on Host12_2

# Forward external port 8080 to Host12_2:80 (OpenStack Horizon or custom app)
/ip firewall nat add chain=dstnat in-interface=ether1 \
  protocol=tcp dst-port=8080 \
  action=dst-nat to-addresses=10.10.255.2 to-ports=80 \
  comment="Inbound: web → Host12_2:80"

8.2 Example: Expose SSH to a specific host

# Forward external port 2201 to Host34_1:22
/ip firewall nat add chain=dstnat in-interface=ether1 \
  protocol=tcp dst-port=2201 \
  action=dst-nat to-addresses=10.10.255.11 to-ports=22 \
  comment="Inbound: SSH → Host34_1"

8.3 Firewall addition needed for DNAT

# Allow forwarded DNAT traffic (add BEFORE the drop-invalid rule):
/ip firewall filter add chain=forward action=accept \
  in-interface=ether1 connection-state=new connection-nat-state=dstnat \
  comment="Allow DNAT forwarded connections"
Security Warning

Every DNAT rule exposes an internal host to the internet. Limit external ports to exactly what is needed, and ensure the target VM/service has its own authentication and hardening.

9. Verification Commands

9.1 From the deployer machine (Ansible)

# Full verification pass:
ansible-playbook playbooks/deploy_exit_routers.yml -i inventory/hosts.yml --tags verify

# Quick BGP check:
ansible-playbook playbooks/deploy_exit_routers.yml -i inventory/hosts.yml --tags verify --limit Exit_Router1

9.2 From the exit router (RouterOS CLI)

# BGP session state:
/routing bgp session print detail

# Routes received from border-leaf:
/ip route print where bgp

# NAT rules active:
/ip firewall nat print

# Firewall counters:
/ip firewall filter print stats

# Ping internet from router itself:
/ping 8.8.8.8 count=3

# Ping a fabric host (verify return path):
/ping 10.10.255.1 count=3

9.3 From a host server (end-to-end test)

# Test egress (internet):
ping -c 3 8.8.8.8
curl -s -o /dev/null -w "%{http_code}" https://google.com

# Trace the path to internet:
traceroute -n 8.8.8.8

# Check which default route FRR has:
vtysh -c "show ip route 0.0.0.0/0"

# Verify ECMP (should show 2 next-hops):
ip route show default

11. Troubleshooting

SymptomLikely CauseFix
Host cannot ping 8.8.8.8 No default route in FRR / BGP not established Check vtysh -c "show bgp summary" on border-leaf; verify exit router BGP sessions
BGP session stays in Connect state /31 link misconfigured or speed mismatch Verify 10.0.253.x IPs on both sides; check sfp+1 speed matches Ethernet0 breakout speed
Host gets response from internal but not external NAT masquerade not applied or ether1 has no external IP Check /ip firewall nat print on exit router; verify ether1 has a routable IP
External user cannot reach internal service Missing DNAT rule or firewall blocks DNAT forwards Add DNAT rule + firewall accept for connection-nat-state=dstnat
Asymmetric path (traffic enters via Router1, exits via Router2) ECMP load balancing; normal behavior Not a problem — masquerade uses conntrack; reply follows same NAT state
deploy_day1_v2.yml --limit border_leaves,exit_routers fails with "no interfaces match" Old sonic_fabric/main.yml doesn't include exit_interfaces Use deploy_day1_v2.yml which references sonic_fabric/tasks/main_v2.yml
